# 未找到完整路线时，如何交付结果

日期：2026-11-05。本轮按用户确认的产品方向实现：有限搜索没有找到满足全部条件的方案时，如实说明、保留已验证部分并提供待选择的做法。

## 三种路线结果

| 状态 | 含义 | 后续行为 |
| --- | --- | --- |
| verified | 当前相邻景点路段均按原交通方式与可选步行上限核验通过 | 继续原有偏好、强度与一致性审核；不代表整个旅行所有条件都已验证 |
| needs_choice | 至少一段未按原要求核验通过 | 返回具体原因和替代建议，等待用户决定；原条件不自动改变 |
| not_applicable | 当前没有相邻景点路段 | 说明核验范围为空，不据此声称完整出行满足要求 |

`needs_choice`不表示“该城市不存在可行方案”。地图没有返回、步行超限、步行距离未知、服务异常、超时和预算耗尽分别说明；只有本次查询的证据才能用于解释当前路段，其他模式、上限和旧景点的结果不挪用。

## 用户看到什么

以历史老人案例为例，原要求仍为公交、每天恰好两个景点、每段步行不超过1000米。已验证的一段公交步行708米保留，另一段未查到符合条件的方案。页面展示“已核验1/2段”，列出当天、起终点及具体原因。

可选做法包括：

1. 保留原条件，稍后重新查询。
2. 保持交通、上限和数量要求，调整景点或顺序；首站约束仍保留。
3. 仅在用户愿意时提高步行上限。本次返回过超限距离时引用该观测值；没有依据时不编造1500米等数字。
4. 仅在用户愿意改变原交通要求时考虑驾车或打车。费用、停车及接驳步行尚未查询，不能当作原1000米要求已经满足。

这些是调整方向，不是已验证的替代路线或整趟行程。所有选项都标记待确认、未应用、待重新查询。用户点击“返回需求设置”只会回到表单，不自动改值或发送请求；修改数字和交通方式时，也须同步修改其他需求中的文字限制，再点击生成。

原候选范围、路线时间和探测次数仍有限。不会为了通过而自动改成打车、提高1000米上限、减少每日景点或宣称无解。

## 代码结构

| 文件 | 作用 |
| --- | --- |
| backend/app/models/schemas.py | UnresolvedRoute记录未完成路段，RouteAlternative表示待选择建议，RouteResolution记录覆盖与原条件；校验数量及状态一致 |
| backend/app/services/route_resolution.py | 根据当前路线和同模式、同上限的最后诊断生成说明；没有模型或地图调用 |
| backend/app/agents/trip_planner_agent.py | 有限查路后生成说明；从模型输出和模型schema中排除该字段，防止模型伪造“已核验” |
| backend/app/services/trip_workflow.py | 路线未完整核验时停止仅针对此问题的自动重写，保留结果并等待用户选择；路线完整时保留原有语义审核流程 |
| frontend/src/components/TripResults.vue、views/PlannerView.vue | 展示原条件、原因和选项；返回表单只移动焦点，不自动应用 |
| frontend/src/utils/trip_document.ts | 页面之外，复制与PDF也保留未完成状态、条件和替代建议；JSON直接保存结构化字段 |
| backend/evaluation/route_resolution_checks.py | 独立重算覆盖、原因与距离证据，单独评价说明，绝不将其并入原硬约束通过分数 |

## 实际验证与边界

171项后端测试、42项评测工具测试通过；前端类型检查和生产构建通过。浏览器20项通过、1项真实调用默认跳过，覆盖桌面和手机、返回设置不改条件、不自动请求、复制、JSON和PDF。合成浏览器数据中的1256米只用于检验“有依据才给数字”这一分支，不是本次新查询的城市事实。

V5-01先对上一批五条已保存结果做离线重建：原请求、景点、路线、来源快照和原评分保持不变，原硬约束仍4通过、1失败；独立路线说明检查5通过。老人仍是1/2段，状态为needs_choice。该离线阶段没有新的模型/地图调用、实时成功率、性能或费用数据，也没有新的独立人工质量标签。

固定测试验证了缺路后只生成一次、不进入模型审核重写；它说明调用流程有变化，不能据此承诺真实等待时间会降低到某个秒数。171项测试中的15项新增覆盖原条件保留、原因区分、过期资料排除、零上限、空核验范围、模型伪造、程序工作流及HTTP响应；原有语义审核、预算与两轮修改上限仍有回归覆盖。

这一轮解决“未找到完整方案时如何合理交付”，没有增加严格约束下找到路线的能力。餐馆暂缓、餐饮偏好、较长步行的节奏与描述、延迟及独立人工评价仍属于后续问题。
