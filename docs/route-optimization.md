# 路线约束优化与已知问题

更新日期：2026-11-04。本次更新是完成的路线优化与评测工具阶段，餐饮衔接和来源证据采集尚待后续实现。

## 为什么修改

老人出游开发样例要求每天恰好两个景点，景点间只用公共交通，每段方案中的步行总距离不超过1000米。旧版一段缺失，另一段返回2384米步行方案。第一次改进加入严格筛选，但固定首站的修复方式可能漏掉需要同时更换两处景点的可行组合。

## 实现

- 新增可选`max_leg_walking_m`（0～50000米），适用于相邻景点间步行或公交接驳步行；驾车不能同时设置该约束。不含景点内部和酒店、餐馆接驳。
- 地图返回多方案时只接受步行已知且不超限者，再比较耗时；未知不补0。规划器独立复核路段、模式及步行距离。
- 先小范围修复，不可行时在已验证有向边中寻找相同景点数的组合，默认允许替换首站，不引入其他天已使用的新景点。只提交经过验证的受影响路段。
- 请求内跨修改轮次复用成功和明确失败；临时失败最多实际尝试两次。诊断区分可用、超限、步行未知、无路线、缺坐标、服务/解析失败、超时及预算耗尽。
- 每次生成共享60秒路线预算，每天最多12次、总共24次额外候选边探测；路径搜索最多扩展2000次。它不是穷举或全城最优规划，不保证找到可行解。
- `preserve_first_attraction: true`保留每日首站，约束模型修改与程序修复；不等于任意必游景点或预约锁定。开启顺序优化也保留其固定首站约定。
- 审核前由代码检查必要路线和数值上限，失败不能被模型判为通过。原有最多2轮修改与180秒额外预算保留。

主要文件：`route_policy.py`统一距离口径，`route_search.py`管理结果与路径搜索，`amap_service.py`解析筛选，`trip_planner_agent.py`组织修复，`review_agent.py`执行审核，`schemas.py`定义约束与诊断，`PlannerView.vue`提交步行上限。
